# Root Cause Fixes — Round 7

## Problem: PDCA Loop Sends Conflicting Commands Every Cycle

The PDCA loop was sending `move izlude`, `move prt_fild00`, `move prt_fild05`, `sit`, `ai auto` all in the same 3-second window. The bot couldn't commit to any action and kept cycling between conflicting commands.

## Root Cause Fix: Committed Action Guard

**File:** `plugins/aiSidecarBridge/aiSidecarBridge.pl`

Added a package-level `%_committed_actions` hash that tracks the last time each action type was sent. If a conflicting action is sent within 30 seconds, it's blocked.

- `move <map>` — blocks other `move <map>` commands to different maps for 30s
- `set lockMap` — blocks other `set lockMap` commands for 30s
- `sit` — blocks `move` commands for 30s
- `ai auto` — always allowed (no conflict)

## Fix: Potion Spam (5-Minute Cooldown When 0 Potions)

**File:** `plugins/aiSidecarBridge/aiSidecarBridge.pl`

The `use <item>` handler now checks if the bot has ANY potions in inventory. If 0 potions, the cooldown extends from 30s to 5 minutes (300s). This prevents the PDCA loop from spamming `use red_potion` 100+ times per session.

## Fix: NPC Teleport Failures

**File:** `tables/portalsLOS.txt`

Stale portal entries at `prontera 156 229` were commented out. The entries at `prontera 157 40` and `prontera 157 38` were already commented out from a previous fix. The `portalsLOS.txt` file is runtime-generated by OpenKore and will self-correct on next startup.

## Fix: Hunting Map Stickiness

**File:** `plugins/aiSidecarBridge/aiSidecarBridge.pl`

When the bot is on a hunting map (`prt_fild*`, `gef_fild*`, etc.) with HP >= 20%, the bridge blocks:
- `move <town>` commands (keeps bot on hunting map)
- `set lockMap <town>` commands (updates lockMap to current map instead)

When blocking a town move, the bridge also:
- Sets `attackAuto` to 3 (aggressive)
- Sets `attackAuto_inLockOnly` to 0 (attack anywhere on map)
- Sets `sitAuto_hp_lower/upper` to 0 (don't sit)
- Runs `stand` and `ai auto` commands
- Clears AI sequence to force immediate transition to attack

## Fix: Skills Add Cooldown

**File:** `plugins/aiSidecarBridge/aiSidecarBridge.pl`

Added `ref()` checks to prevent "Not an ARRAY reference" crash when `$char->{skills}` is not an array. 30-second cooldown on `skills_add` commands.

## Fix: Coroutine Await Warning

**File:** `AI_sidecar/ai_sidecar/memory/long_term_memory.py`

Changed from `asyncio.run()` to `new_event_loop()` + `run_until_complete()` to fix "coroutine 'Memory.add' was never awaited" warning.

## Fix: Validation Noise

**File:** `AI_sidecar/ai_sidecar/app.py`

Changed `http_request_validation_failed` from `logger.warning()` to `logger.debug()` to reduce log noise.
